# Dispatch contract

Write a fresh prompt for each bounded task. Omit empty sections; never leave placeholders for the executor to guess.

```text
ROLE AND AUTHORITY
You are the executor (or read-only reviewer) for this task. The orchestrator owns plans, architecture, design rulings, and acceptance. Report design gaps; do not decide scope or self-accept. Follow repository instructions. Do not commit, push, publish, reset, stash, clean, or change unrelated files unless this task explicitly authorizes it.

WORKSPACE
Repository, branch, worktree: ...
Existing changes to preserve: ...
Other executors working in parallel and the files they own (do not touch): ...

GOAL AND SOURCES
Outcome: ...
Behaviour contract and rule IDs this task must satisfy: ...
Rulings with their evidence (live measurements, code facts, recorded decisions that must not be reversed): ...
Rejected approaches (and why), if a previous attempt failed: ...

BOUNDARY
Allowed edits: ... (or "Read-only; make no edits")
Excluded paths and actions: ...
Structure: module layout, file-size and layering rules: ...
Decisions to report instead of making: ...

ACCEPTANCE AND VERIFICATION
Observable conditions: ...
Tests to write (name each, with the rule ID in its title): ...
Commands, run synchronously and waited for: format/lint; the COMPLETE test set of every package you touched (not only edited files); type check; touched UI specs; structure guards. In a parallel batch these targeted checks are all; the orchestrator runs the full suites on the merged result.
Environment: build lock, parallelism caps, headless/silent tests (no real shell, picker, or opener calls), distinct dev-server port.
Failing tests are contracts: if one conflicts with the task, stop and report it — never loosen assertions or edit shared fixtures outside the boundary.
Editing: use your patch/edit tool; keep line endings; no machine-specific paths in tracked files; no scratch files.
If a command did not finish, say so instead of reporting success.

REPORT
Status: IMPLEMENTED_PENDING_REVIEW / READY_FOR_REVIEW / BLOCKED(reason)
Changed files and raw verification lines (test names and summary lines, not paraphrase): ...
Per rule ID: where it is implemented (file, function) and how the runtime path works: ...
Deviations, open questions, failures: ...
```

For failover, prepend a handoff: prior session ID, `git diff --stat`, last result, unfinished items. For a read-only review, request findings with severity, location, evidence, and a concrete correction, then verify that no writes occurred. The orchestrator evaluates findings and owns the verdict.
